## Ledger Rules
目前 migration 採 signed delta 快取餘額，不是完整多行會計科目總帳終局版，但已能讓帳戶餘額隨交易變動。

- 資產帳戶支出：`balance -= amount`
- 信用卡 / 負債帳戶支出：`balance += amount`
- 資產帳戶收入：`balance += amount`
- 負債帳戶收入：`balance -= amount`
- 轉帳來源：
  - 資產來源：`balance -= amount`
  - 負債來源：`balance += amount`
- 轉帳目標：
  - 資產目標：`balance += amount`
  - 負債目標：`balance -= amount`
- 刪除交易時：
  - 依原本 `family_ledger_entries.amount_delta` 反向套用。

## Risks / Gotchas
- 現有舊交易不會自動補 ledger entries，這是刻意避免把已存在的 `family_accounts.balance` 重複調整。
- 如果需要舊交易也補分錄，必須另外寫一次性 backfill，並先決定現有帳戶 balance 是「真實目前餘額」還是「應由歷史流水推導」。
- `family_accounts.balance` 目前 schema 有 `check (balance >= 0)`，因此任何會讓帳戶變負的交易會被 DB trigger 拒絕。這對信用卡/負債是合理的，但對銀行透支或現金負數暫時不支援。
- 多幣別目前仍未換算；ledger entry 記錄 currency，但 balance 仍是帳戶原 currency 的數值概念。
- `createAdminClient()` 使用 service role key，RLS 不是主要防線。後續若要正式多家庭/多使用者隔離，必須補 household_id 到 `family_accounts` / `family_transactions` / `family_ledger_entries`。
- Production 已部署前端，但 DB migration 未套用，這是目前最大的半成品風險。
- 工作樹有大量既有未提交/未追蹤檔，不要用 destructive git command 清理。
